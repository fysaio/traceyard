# Traceyard frontend audit

The product journey is to understand the value before sign-in, start with GitHub, investigate a failure, and verify a repair with the original test. Connecting a coding agent is optional. Authorize the agent first and grant access to a project when a task needs it.

## Screen findings

| Surface                                   | Friction                                                                                                                                                     | Change in this release                                                                                                                                                                         |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Landing and sign-in                       | A sign-in button asked for commitment before showing the job Traceyard does.                                                                                 | A readable promise, one GitHub sign-in action, and an interactive example that shows a failed test and the same test passing after a fix. The example is labeled and requires no account.      |
| Investigations                            | The same repository appeared in the header and inside the composer. Test execution and source-only inspection were easy to confuse.                          | Keep repository context in the header, explain what investigation does next, and show the test path before submission. Commit and recording settings have a labeled disclosure with a chevron. |
| Investigation result                      | The original question could be a paragraph containing commit IDs. It pushed the finding and next action down. Counts and status appeared in multiple places. | Give the finding and test output priority, keep the original question and ID under a disclosure, and surface repair verification after failure. Omit the empty evidence container.             |
| Repository setup                          | Readiness badges repeated the same installation and execution state across panels. Several actions looked equally important.                                 | Show readiness together and prioritize the action that moves the user forward. Retain details about the repository and workflow permissions.                                                   |
| Repositories                              | “Completed” could describe setup or the last check. Empty cards repeated recording counts.                                                                   | Label the last check explicitly and show counts where there are recordings.                                                                                                                    |
| Connections                               | The workspace required a project to open Connections, even though agent authorization was account-wide.                                                      | Expose agent setup and access management on a fresh account. Keep repository setup and project access controls scoped to a selected project.                                                   |
| Workspace navigation and tools            | Search disappeared at the smallest widths, project selection could crowd other controls, and tool rows filled more space than their labels needed.           | Preserve search, limit the project switch width, keep primary touch targets at 44 px, and let the tools dialog scroll within the viewport.                                                     |
| Workflows, workflow runs, and experiments | Empty states competed with the same action in the header. The experiment form opened without an expanded state on its button.                                | Use one primary action for each empty state. Label the form toggle and indicate when it is open.                                                                                               |
| Approvals and setup navigation            | Some links labeled “Workflows” opened Investigations. Setup pages pointed back to the workspace home.                                                        | Send the user to the named destination and preserve their project context.                                                                                                                     |

## Verification

- Playwright covers the anonymous example and sign-in destination, including keyboard activation and reduced motion. The screenshot matrix includes Chromium at 320, 390, 768, and 1440 CSS px.
- The same width matrix checks the signed-in workspace routes for overflow and page errors. Existing journeys cover opening saved evidence, reopening a repair verdict, account-first agent authorization, and workflow execution.
- The workspace route sweep covers Investigations, Connections, Repositories, Workflows, Workflow runs, Runtime traces, Approvals, Gateway, Laboratory, Connect, and each settings destination. The route sweep checks shell and screen layout. Separate journeys assert the investigation, agent authorization, and workflow behaviors.

## Remaining product checks

- Time the first real investigation and repair from a new GitHub account and repository. Browser sign-in and the example do not install the GitHub App or enable test execution. Source-only analysis can begin when repository access is available; execution requires the supported runner setup and a runnable test.
- Test the layout on Safari and Firefox and perform a screen-reader pass with an assistive technology user. Playwright's viewport matrix uses Chromium.
- Check individual remote MCP clients for their built-in connection flow. Traceyard's account-first OAuth and later per-project access are exercised with a protocol client. A client can still have a manual server URL field.
