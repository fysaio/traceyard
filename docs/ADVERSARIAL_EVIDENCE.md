# Adversarial evidence coverage

This matrix records the deterministic evidence coverage for issue [#72](https://github.com/fysaio/traceyard/issues/72). It is an audit of the selected evidence paths, not a security certification or proof that hostile repository code cannot defeat every test runner.

The read-only audit baseline was merged `main` revision `4554a12` (the merge of PR #113). The issue-targeted baseline commands passed before the changes in this branch:

- `npm run test:unit -- tests/unit/evidence-contract.test.ts tests/unit/adversarial-evidence.test.ts tests/unit/local-evidence.test.ts tests/unit/hosted-evidence.test.ts` — 4 files, 67 tests passed.
- `npm run test:integration -- tests/integration/investigation-execution.test.ts tests/integration/verifications.test.ts` — 2 files, 18 tests passed.

After adding the report-revision regression and matrix, the same targeted suites passed with 68 unit tests and 18 integration tests. The full `npm test` suite passed with 26 files and 215 tests; `npm run typecheck`, `npm run lint`, `npm run build`, and `npm run build:managed` also passed. Changed-file Prettier checks and `git diff --check` passed.

## Omitted-check boundary

The evidence contract can safely reject or downgrade checks that are present with `NOT_RUN`, `FAILED`, `SKIPPED`, `BLOCKED`, or `CANCELLED` status, and it rejects an empty pass envelope. It cannot infer that a missing entry was required without an authoritative expected-check set. Current verification evidence is `FOCUSED` and contains the checks derived from the recorded test and comparison facts; it does not claim `REQUIRED_PASS`.

That unresolved distinction is intentionally retained as a limitation instead of being hidden by a synthetic list of required checks. A future policy/contract change must define the expected set, bind it to the repository and revision, and add fixtures for an absent required check before any path may claim `REQUIRED_PASS`.

## What this matrix does not prove

Passing these fixtures does not attest the correctness of repository code, prove complete hostile-code isolation, restrict network egress, or turn a selected-test result into generic merge approval. Hosted verification remains `HOSTED_UNATTESTED`, and local evidence remains `LOCAL_PROVISIONAL`.
